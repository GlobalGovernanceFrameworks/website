## How to Use This Framework

This is not a document to read cover-to-cover. It’s a **toolkit**—open it, find what you need, adapt it, use it, and share what you learn.

1. **Know Your Context** → Use the **Tool Finder** (Section 3) to get recommendations
2. **Pick a Tool** → Grab the **Resource Card** (Appendix B) to see what it costs in time, people, and money

4. **Pilot It** → Follow the **Pilot Feedback Template** (Appendix E)
5. **Share What You Learned** → Add your story to the **GGF Story Bank** (Appendix I)

## 1. Introduction: The GGF’s Operating Manual

### The Problem
Visionary frameworks fail without practical, adaptable tools. A “one-size-fits-all” approach cannot work across diverse cultural, political, and economic contexts.

### The Opportunity
A living library of governance tools that are **modular, interoperable, and ethically grounded**—bridging the “what” (GGF’s vision) and the “how” (practical steps).

### The Core Function
Provide any GGF actor—from a village council to an interstellar commission—with **field-tested tools** that work in their context.

### Who Is This For?

| User | How They Use This Framework |
|------|----------------------------|
| **Community Weaver** | Find tools for your village, neighborhood, or group |
| **BAZ Coordinator** | Build governance structures for your bioregion |
| **Facilitator** | Get guides, templates, and training pathways |
| **Elder / Knowledge Keeper** | Adapt tools to oral traditions and cultural practices |
| **Digital Steward** | Implement tech tools with sovereignty and accessibility |
| **Crisis Responder** | Activate emergency protocols under pressure |

## 2. Guiding Principles

### 2.1 Low-Tech First, High-Tech Enabled
Every digital tool has an **analog companion**. No community is excluded due to technology access.

### 2.2 Polycentric & Subsidiarity-First
Tools empower the **most local effective governance level**. Higher levels only act when local cannot.

### 2.3 Culturally Plural, Not Universal
No tool is imposed. Communities **adapt, fork, and own** their tools. Western facilitation norms are optional, not default.

### 2.4 Anti-Colonial by Design
Tools are co-designed with Indigenous and Global South leadership. Communities can **veto** tools they didn’t consent to.

### 2.5 Modular & Interoperable
Tools are “Lego blocks.” Mix and match. If a tool doesn’t fit, swap it out.

### 2.6 Harm-Aware, Not Harm-Naive
Every tool includes **harm prevention protocols**. If a tool causes harm, communities can pause, remediate, or retire it.

### 2.7 Human-in-the-Loop
AI and technology serve **human wisdom and ethical oversight**, not the reverse.

### 2.8 Accessible by Design
All tools meet **accessibility standards** (visual, auditory, cognitive, motor, sensory) with **crip time** flexibility.

## 5. Analog Companion Guides

Every digital tool has an **analog version**. Here’s the mapping:

| Digital Tool | Analog Equivalent | Materials | Skills Needed |
|--------------|-------------------|----------|---------------|
| Pol.is / deliberation platform | Talking circle with consensus stones | Stones or tokens; circle seating | Deep listening; conflict mediation |
| Digital Asset Passport | Community ledger with witnesses | Bound notebook; trusted recorders | Literacy; impartiality |
| VR/AR training | Storytelling + role-play | Open space; experienced storytellers | Narrative facilitation; embodiment |
| AI-assisted translation | Human translators + interpreters | Language speakers; translation budget | Cultural bridge-building |
| Blockchain verification | Community witnesses + rotating auditors | Trusted community members | Neutrality; documentation |
| Digital voting | Paper ballots + public counting | Paper, box, counters | Transparency; verification |
| Online deliberation | Village meeting + talking stick | Meeting space, talking stick | Facilitation; agenda-setting |

### 5.1 Offline-First Design Standards

All tools must have:
- **Paper-based version** – Printable guides, templates, worksheets
- **Audio version** – For oral traditions and low-literacy communities
- **Facilitator script** – Word-for-word guidance for first-time facilitators
- **No-internet option** – Can be run entirely without connectivity
- **Local materials** – Uses locally available materials, not specialized supplies

### 5.2 Connectivity Tier System

| Tier | Connectivity | Tool Adaptation |
|------|--------------|-----------------|
| **Tier 0** | No connectivity | Analog-only; offline storage; human messengers |
| **Tier 1** | Intermittent SMS | Text-based tools; asynchronous; store-and-forward |
| **Tier 2** | Basic internet | Lightweight web tools; text-first; low-bandwidth |
| **Tier 3** | High-bandwidth | Full digital suite; VR/AR when appropriate |

## 6. Cultural Adaptation Protocols

### 6.1 Before Using Any Tool, Ask:

| Question | If Yes → | If No → |
|----------|----------|---------|
| Does this tool conflict with local governance traditions? | Adapt or replace | Proceed |
| Who are the legitimate decision-makers in this community? | Respect existing authority | Map stakeholders |
| What is the community’s relationship to technology? | Match comfort level | Start with analog |
| What is the role of elders/youth/women in decision-making? | Don’t disrupt existing roles | Clarify roles |
| How is knowledge traditionally transmitted? | Align with (oral/written/digital) norms | Adapt format |

### 6.2 Cultural Governance Templates

Communities can submit their own governance templates to the library:

| Template Type | Example Traditions | Use Case |
|---------------|-------------------|----------|
| **Consensus Models** | Māori hui, Indigenous talking circles, Islamic shura | Replace Western consensus models |
| **Decision Documentation** | Oral tradition, wampum belts, carved records | Replace written minutes |
| **Leadership Structures** | Elder councils, matriarchal systems | Replace Western hierarchies |
| **Conflict Resolution** | Restorative circles, peacemaking, sulha | Replace litigation models |

### 6.3 Indigenous Co-Design Standard

Tools using Indigenous methodologies require:
- **Minimum 40% Indigenous participation** in tool design
- **FPIC 2.0 protocols** for knowledge use
- **Benefit-sharing** for commercialized tools
- **Community veto power** over adaptations without consent
- **Certification** by the Cultural & Ancestral Wisdom Council

## 7. Tool Governance: The “GitHub” Model

### 7.1 Fork, Don’t File

Instead of a 7-stage bureaucratic TIP process, treat tools like open-source software:

| Action | Process |
|--------|---------|
| **Use a tool** | Just use it. No permission needed. |
| **Adapt a tool** | “Fork” it. Change what doesn’t work. Use your version. |
| **Share an adaptation** | Publish back to the library as “[Community Name] Variant” |
| **Rate a tool** | 1-5 stars on effectiveness, cultural fit, ease of use |
| **Report harm** | Flag for review; tool suspended pending assessment |
| **Retire a tool** | If no one uses it for 3 years, it moves to archive |

### 7.2 Tool Versioning

| Element | Standard |
|---------|----------|
| **Core Tools** | Maintained by GGF; updated with community input |
| **Community Variants** | User-submitted; attributed to originating community |
| **Fork Registry** | All adaptations tracked; credit maintained |
| **Sunset Notices** | 12-month notice before retirement; migration support |
| **User Choice** | Communities may stay on older versions |

### 7.3 Tool Rating System

Community-driven ratings displayed on every tool:

| Category | Rating | Source |
|----------|--------|--------|
| **Effectiveness** | ⭐ 1-5 | User feedback |
| **Cultural Fit** | ⭐ 1-5 | Cultural Council assessments |
| **Ease of Use** | ⭐ 1-5 | Facilitator ratings |
| **Resource Intensity** | 💰 Low/Med/High | Resource cards |
| **Trust Score** | ✓ 1-5 | Community trust surveys |

## 8. Harm Prevention & Remediation

### 8.1 Tool Misuse Early Warning Indicators

| Indicator | Red Flag | Response |
|-----------|----------|----------|
| **Capture** | Tool consistently benefits one group | Audit facilitator neutrality; community veto option |
| **Exclusion** | Marginalized groups stop participating | Mandatory inclusion review; reparative process |
| **Technical Coercion** | “Digital-only” excludes low-tech users | Require analog alternative |
| **Surveillance** | Tool collects data without consent | Shut down; data deletion; community review |
| **Spiritual Harm** | Tool disrespects sacred practices | Immediate suspension; Cultural Council review |

### 8.2 Harm Remediation Protocol

When a tool causes harm:

1. **Immediate Pause** – Tool use suspended pending review
2. **Harm Documentation** – Community-led documentation of impacts
3. **Cultural Council Review** – Assessment by Cultural & Ancestral Wisdom Council
4. **Remediation Plan** – Community-designed repair (not framework-imposed)
5. **Tool Revision or Removal** – Based on community recommendation
6. **Reparations** – Funded via Global Commons Fund for irreparable harm
7. **Learning Documentation** – Added to GGF Failure Library (anonymized)

### 8.3 Community Veto Power

Any community using a tool may:
- **Pause** tool use at any time without penalty
- **Request review** by Cultural & Ancestral Wisdom Council
- **Veto** tool modifications they did not consent to
- **Exit** the tool ecosystem entirely with data portability

## 9. Accessibility by Design

### 9.1 Accessibility Requirements Matrix

| User Need | Requirement | Verification |
|-----------|-------------|--------------|
| **Visual** | WCAG 2.1 AA minimum; screen reader compatible | Automated + manual audit |
| **Auditory** | Captions; transcripts; sign language options | User testing |
| **Motor** | Keyboard navigation; voice control | Assistive technology testing |
| **Cognitive** | Plain language; visual aids; no time pressure | Neurodiverse user testing |
| **Sensory** | Adjustable intensity; quiet modes; no flashing | Sensory sensitivity testing |
| **Learning** | Multiple formats; scaffolding; repetition | Diverse learner testing |

### 9.2 Crip Time Integration

All tools respect **crip time** principles:
- No mandatory real-time participation without asynchronous alternative
- Flexible timelines; no arbitrary deadlines
- Rest breaks built into all facilitated processes
- Accommodations are standard, not exceptional

### 9.3 Cognitive Accessibility Protocol

| Feature | Requirement |
|---------|-------------|
| **Plain Language** | All materials available at 6th-grade reading level |
| **Visual Supports** | Icons, diagrams, and visual summaries for all text |
| **Executive Function Support** | Checklists, templates, and step-by-step guides |
| **Processing Time** | No time-limited activities without alternatives |
| **Trauma Awareness** | Trigger warnings; opt-out options; support resources |

## 10. Pilot Testing Framework

### 10.1 Pilot Success Criteria

| Metric | Tier 1 (Tool Test) | Tier 2 (Stack Trial) | Tier 3 (Full Journey) |
|--------|---------------------|----------------------|------------------------|
| **Completion** | Tool used as designed | Stack components all piloted | All journey milestones met |
| **User Satisfaction** | >70% positive feedback | >80% positive feedback | >90% positive feedback |
| **Cultural Fit** | No significant misalignment | Adaptations documented | Community ownership achieved |
| **Outcome Achievement** | Pilot goals met | Intermediate outcomes | Long-term outcomes trending |
| **Scalability** | Not applicable | Replicable in 2+ contexts | Ready for broader adoption |

### 10.2 Pilot Feedback Template

| Section | Questions |
|---------|----------|
| **Cultural Fit** | Did the tool respect local traditions? What adaptations were needed? |
| **Technical Performance** | Did digital tools work as expected? What connectivity issues arose? |
| **Facilitator Experience** | Was facilitation clear? What support would have helped? |
| **Participant Experience** | Did participants feel heard? Were barriers to participation identified? |
| **Unexpected Outcomes** | What worked that wasn’t anticipated? What problems emerged? |
| **Recommendations** | Should this tool be revised, scaled, or retired? |

### 10.3 Scaling Decision Tree

```
Pilot Complete
│
├─► [Success + Cultural Fit] → Scale to Tier 2 (Stack Trial)
│   └─► [Success + Cultural Fit] → Scale to Tier 3 (Full Journey)
│       └─► [Success + Cultural Fit] → Tool certified for ecosystem
│
├─► [Success + Adaptation Needed] → Revise tool; re-pilot
│
├─► [Mixed Results] → Document in Failure Library; revise
│
└─► [Failure + Harm] → Tool retired; reparations; Failure Library entry
```

## 12. Monitoring, Evaluation & Learning

### 12.1 Real-Time Feedback Channels

| Channel | Purpose | Integration |
|---------|---------|-------------|

*Failure Library is managed by the Knowledge Commons Ombudsperson and is a required read before piloting new tools.*
