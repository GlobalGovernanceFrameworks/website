## 現状について

現在、このサイトは英語、スウェーデン語、日本語で存在しています。英語が原言語であり、他の2言語を大きく先行しています。スウェーデン語と日本語はインターフェースと一部のフレームワークのコンテンツをカバーしていますが、大きな欠落があります。

翻訳チームも、レビュー委員会も、コーディネーターも存在しません。もしあなたが、ここにいる誰も読めない言語に何かを翻訳した場合、それをチェックできる人は誰もいません。つまり、品質管理はあなた自身の注意深さにかかっています。後で気づくよりも、最初に知っておく価値があります。

新しい言語を追加することは完全に可能です。それは単に、あなたがその言語で作業する最初の人になるということです。

## 最初に翻訳する価値があるもの

**インターフェーステキスト** は `src/lib/i18n/[locale]/*.json` にあり、ページや機能ごとに分割されています。これらのファイルは短く、自己完結しており、すぐに目に見える形で反映されます。初めての貢献として適しており、ある言語をそもそも使えるようにする最速の方法です。

**フレームワークのコンテンツ** は `src/lib/content/frameworks/[locale]/` にあります。これらは長文のMarkdown文書です。一つのフレームワークが数万語に及ぶこともあるため、セクションごとに翻訳するのが普通であり歓迎されます。部分的な翻訳は全く無いよりはるかに優れており、欠けている部分についてはサイトは英語にフォールバックします。

**フレームワークの概要** は両者の中間に位置します。高レベルの要約で、それぞれ数百語程度であり、作業時間あたりの価値が最も高いでしょう。

ロケールフォルダには標準のISO 639-1コードを使用してください: `es`, `fr`, `de`, `pt`, `ar`, `zh`, `hi`, `ru` など。

## 翻訳の原則

**優雅さより正確さ。** これらは政策文書です。専門的な概念が正確である場合、結果がやや堅苦しく読めても、その正確さを保ってください。

**文書内での一貫性。** 繰り返し出てくる用語に対して一つの訳語を選び、それを使い続けてください。あなたがその言語への最初の翻訳者ならば、あなたがその慣例を設定することにもなります。自分の選択を書き留めておくことは、3ヶ月後の自分自身を含め、後から来る人の助けになります。

**助けになる場合の文化的適応。** 例や参照は、あなたの文脈に合わせて適応させることができます。実質的な主張は変更できません。

**能動態、可能であればジェンダーニュートラルに。** フォーマルでありながら読みやすく。

### 翻訳しないもの

固有名詞（国連、IPCC）、確立された頭字語（AI、GDP、CO₂）、そしてフレームワーク名――「Global Governance Frameworks」「Treaty for Our Only Home」「Hearts」「Leaves」といった造語は、説明ではなく名前として機能します。

### 翻訳するが、一貫して

政策概念（ガバナンス、持続可能性、レジリエンス）、実装用語（アセスメント、モニタリング、評価）、社会的概念（コミュニティ参加、ステークホルダー関与）。

## 翻訳者を悩ませる用語

| 用語 | 意味 | 備考 |
|---|---|---|
| **Polycrisis（ポリクライシス）** | 相互に関連した複数の危機が同時に発生すること | 比較的新しい造語；初出時に注釈が必要な場合があります |
| **Ecocide law（エコサイド法）** | 深刻な環境破壊を犯罪とする法的枠組み | 独自に造語する前に、あなたの法域における同等の概念を調べてください |
| **Bioregion（バイオリージョン）** | 政治的境界ではなく生態学的境界によって定義される地域 | 確立された用語がある言語もあれば、ない言語も多い |
| **Right relationship（正しい関係）** | 人と場所との健全な相互関係の中で生きること | 意図的に非技術的な表現；形式化しようとする衝動に抵抗してください |
| **Subsidiarity（補完性原理）** | 可能な限り最もローカルなレベルで意思決定を行うこと | 多くのヨーロッパ言語では確立されたEU政策用語 |
| **Regenerative（再生的）** | 単に維持するのではなく、回復させること | 「Sustainable（持続可能な）」は同義語ではなく、代用すべきではありません |
| **Stewardship（スチュワードシップ）** | 信託されたものに対するケアと責任 | 一語で相当するきれいな訳語が存在しないことが多い |

## スウェーデン語固有の注意点

スウェーデン語ではタイトルケースを使いません。見出しの最初の単語と固有名詞のみを大文字にしてください。英語のようにすべての重要な単語を大文字にすることはありません。

## ワークフロー

`github.com/GlobalGovernanceFrameworks/website` のリポジトリをフォークし、翻訳内容にちなんだ名前のブランチを作成し（例: `translate-treaty-overview-es`）、対象言語のロケールフォルダ内で作業します。フォルダが存在しない場合は作成してください。

```bash
git clone https://github.com/yourusername/website.git
cd website
git remote add upstream https://github.com/GlobalGovernanceFrameworks/website.git
git checkout -b translate-treaty-overview-es
```

Markdownの構造を保持してください。見出し、リスト、リンク、コードスパンはそのまま残す必要があります。知っておくべき一つの癖: mdsvexでは、数字の直前に裸の `<` があるとコンパイルが中断されるため、バッククォートのコードスパンで囲んでください。

準備ができたら、あなたのフォークにプッシュし、翻訳した内容と確信が持てなかった点を説明するプルリクエストを開いてください。不確かな点を明示することは非常に有用であり、将来の翻訳者がどこを確認すべきかを教えてくれます。

## レビューとタイミングに関する現実的な注意点

レビューは、英語とスウェーデン語を読む一人の人間によって行われます。他の言語については、レビューは翻訳の良し悪しではなく、構造的に壊れたものがないかどうかのチェックを意味します。もしセカンドオピニオンが欲しく、それを提供できる人を知っているなら、その人を連れてくることは、より大きなプロジェクトよりもここでは大きな価値があります。

応答時間は様々です。しばらく経った後のDiscordでのリマインドは、失礼ではなく歓迎されます。

## ヘルプを得る

用語や構造、あるいはそもそも翻訳する価値があるかどうかについての質問には、Discordが最速の手段です。規模が小さいため、通常はあなたが作業しているテキストを書いた本人と話をすることになります。
