## Executive Summary

The Global Governance Frameworks (GGF) create a bold vision for regenerative economics – Hearts and Leaves currencies, Proof of Care validation, nested economic coordination, and capture‑resistant meta‑governance. However, several critical vulnerabilities remain underspecified:

- **Collusion rings** can fabricate care transactions to extract Hearts.
- **Sybil attacks** can inflate trust scores or capture participatory votes.
- **Proof of Care** lacks a verifiable, non‑gamifiable mechanism.
- **Cross‑BAZ trust** currently depends on manual relationships or centralised authorities.
- **Meta‑governance capture** detection is described qualitatively, not quantitatively.

The **Immanent Trust Protocol (ITP)** closes these gaps. ITP is a post‑consensus, observer‑relative trust architecture that provides:

- **Trust Independence Metric (TIM):** Mathematically collapses collusion rings – a thousand Sybils endorsing each other have the influence of one honest node.
- **Trust Shock Propagation:** Endorsers have “skin in the game” – if a node defects, its endorsers’ trust weight is temporarily held until restitution.
- **Scale‑Adaptive Fields (SAFs):** Ephemeral, auto‑dissolving coordination structures for cross‑BAZ decisions, with cryptographic time‑to‑live.
- **Local Trust State (LTS):** Each node computes its own trust assessment using only local information – no global ledger, no single point of control.

This document specifies how ITP integrates with the GGF’s Financial Systems, AUBI, Nested Economies, and Meta‑Governance frameworks. It includes a **GGF‑specific adaptation profile** (restorative rather than punitive propagation) and a **three‑phase implementation roadmap** (Hearts Treasury fraud → Proof of Care → meta‑governance voting).

## 1. What Is ITP? (A Short Overview for GGF Readers)

ITP is not a blockchain, a cryptocurrency, or a global reputation system. It is a **protocol for local, observer‑relative trust** – each participant maintains its own **Informal Trust Ledger (ITL)**, a graph of cryptographically signed **Trust Signals** (interactions, endorsements, constraints). Trust is computed at the edge, using only the signals a node has received from its immediate neighbourhood.

**Core mechanisms relevant to the GGF:**

| ITP Mechanism | Purpose | GGF Analogue |
|---------------|---------|---------------|
| **Trust Signal** | A signed claim: “Node A interacted with Node B in context C, outcome value V, confidence X.” | Proof of Care, Love Ledger entry, Community Provider endorsement |
| **Local Trust State (LTS)** | Scalar trust score in [-1,1], computed locally from signals. | LMCI‑A per‑contribution score; BAZ Council member trustworthiness |
| **Trust Independence Metric (TIM)** | Discounts endorsements from nodes with overlapping neighbourhoods. | Collusion ring detection (fake care logs, Sybil votes) |
| **Trust Shock Propagation** | Penalty cascades backward to endorsers when a node defects. | Endorser liability (without financial stake) |
| **Scale‑Adaptive Field (SAF)** | Temporary, self‑dissolving coordination structure with rotating coordinator. | Inter‑BAZ ecological standard setting, crisis response |
| **Distance Attenuation** | Signals from far‑away nodes are heavily discounted (λ=0 at 4+ hops). | Localism / subsidiarity – no global trust override |

**Key properties for the GGF:**
- **No global consensus** – each BAZ computes its own trust; no single ledger can be captured.
- **Sybil‑resistant by topology** – TIM collapses collusion rings regardless of their size.
- **Endorser liability without financial stake** – reputational collateral is universal.
- **Ephemeral coordination** – SAFs prevent permanent bureaucratic capture.

## 2. GGF‑Specific Adaptation Profile

ITP’s default design uses **punitive shock propagation** – endorsers permanently lose trust weight when a node defects. This conflicts with the GGF’s **restorative justice** and **Right Relationship** principles. Therefore, we define a **GGF adaptation profile** that replaces punitive slashing with a **restorative hold** model.

### 2.1 Restorative Hold (instead of permanent reduction)

When a verified defection occurs (e.g., fake care log, Heart redemption fraud):

1. **Freeze** the trust weight of all direct endorsers of the defector. Their existing LTS contributions remain, but new signals from them are temporarily discounted (multiplier = 0.5).
2. **Notification** – the defector and endorsers enter a **resolution period** (default 30 days).
3. **Restitution** – if the defector makes amends (verified by the victim and a Community Weaver), endorsers’ trust weight is fully restored.
4. **Only if restitution fails** and endorsers are proven to have colluded in the fraud, the weight reduction becomes permanent (slashed by Δ = confidence × severity).

This preserves the incentive for endorsers to vet nodes carefully, while allowing genuine mistakes or external shocks to be repaired.

### 2.2 Multi‑Dimensional Trust Signals for LMCI‑A

The AUBI framework requires three‑dimensional scoring (Love, Meaning, Connection). ITP’s default Trust Signal uses a scalar `value`. We extend the schema to support a vector:

```json
{
  "type": "interaction",
  "lmci_scores": {
    "love": 0.85,
    "meaning": 0.70,
    "connection": 0.90
  },
  "confidence": 0.8,
  ...
}
```

Aggregation becomes a weighted sum per dimension. The `context` field determines which dimensions are required.

### 2.3 Context Ontology for GGF Domains

ITP’s `context` field (URI) is extended with a GGF‑specific registry:

| Context URI | Meaning | Required Dimensions |
|-------------|---------|---------------------|
| `ggf:care:proof` | Proof of Care (provider‑recipient) | Love, Connection |
| `ggf:ecology:leaves` | Ecological restoration (Leaves) | Connection (with Green Job Score multiplier) |
| `ggf:governance:vote` | Council vote | None (value = vote choice) |
| `ggf:treasury:redemption` | Heart redemption request | Confidence only |
| `ggf:weaver:endorsement` | Community Weaver endorsement | Confidence, optional Love |

Resolution is managed by the **Social Resilience Council** via a decentralized schema registry (Section 3.5 of ITP whitepaper).

### 2.4 Trust‑Weighted Voting for Meta‑Governance

Instead of one‑person‑one‑vote, councils can use **trust‑weighted voting**:
- Each member’s vote weight = their LTS as computed by the council’s **official trust oracle** (a neutral node or aggregate).
- TIM is applied to the set of voters – if a collusion ring forms, their collective weight collapses.
- This makes Sybil attacks on governance mathematically irrational.

The GGF adaptation profile recommends trust‑weighted voting for:
- BAZ Council elections (within a BAZ)
- Social Resilience Council decisions that affect Hearts issuance parameters
- ICTL (Inter‑Currency Translation Layer) structural changes (Tier B)

## 3. Vulnerability Mappings (How ITP Closes Each Gap)

The following tables map specific vulnerabilities from each GGF framework to ITP mechanisms.

### 3.1 Financial Systems Framework

| Vulnerability (from Financial Systems) | ITP Mechanism | How It Solves |
|----------------------------------------|---------------|----------------|
| Hearts Treasury fraud – fake care logs | TIM | Fake recipients have overlapping neighbourhoods (all endorse the same fake provider). TIM discount τ → 0, so their collective redemption weight collapses. |
| Sybil rings manipulating Hearts supply | TIM + distance attenuation | Sybils cannot scale influence because their endorsements are discounted by TIM and also limited by hop distance (λ=0 beyond 3 hops). |
| Heartstarter match fund abuse | Velocity‑limited accumulation + TIM | A new BAZ cannot reach high trust quickly (Δ_max=0.05/day). Even with many fake transactions, TIM collapses the ring before it can extract match funds. |
| Love Ledger gamification (fake gratitude) | TIM | Fake gratitude accounts share identical neighbourhoods (only interact with the target). TIM discounts them to zero. |
| Inter‑Currency Translation Layer capture | SAFs + TIM | Instead of a permanent ICTL committee, use a SAF for each rate change. SAF auto‑dissolves after TTL; TIM ensures joining nodes are independent. |

### 3.2 Adaptive Universal Basic Income (AUBI) Framework

| Vulnerability (from AUBI) | ITP Mechanism | How It Solves |
|---------------------------|---------------|----------------|
| Proof of Care – fake provider rings | TIM | A provider with 1000 fake recipients: those recipients are Sybils with overlapping neighbourhoods. TIM collapses their collective endorsement weight. |
| Layer 2 bonus gaming | Trust Signal expiry + confidence cap | Each care act is a signed signal with expiry (e.g., 90 days). Confidence is capped at 0.3 for low‑stakes interactions (AUBI Layer 2 uses higher confidence for verified providers). |
| Provider chartering without objective criteria | LTS threshold | A provider is charterable when LTS ≥ 0.7 from at least 10 independent recipients with TIM τ > 0.6. This is auditable. |
| BAZ Council capture (Sybil voters) | Trust‑weighted voting | Each resident’s vote weight = LTS. Sybil residents have low LTS (they only endorse each other, TIM discounts). |
| Stateless population enrollment | Threshold attestation | 3+ Community Weavers with high LTS issue endorsements for the stateless person. No central authority required. |

### 3.3 Nested Economies Framework

| Vulnerability (from Nested Economies) | ITP Mechanism | How It Solves |
|----------------------------------------|---------------|----------------|
| Cross‑BAZ trust without global authority | Trust pathways + distance attenuation | BAZ A trusts BAZ C via a chain A→B→C. Attenuation λ(2)=0.5, λ(3)=0.1. Long chains have negligible influence – keeps trust local. |
| Community Weaver verification quality | Trust Signals from trainees | Each trainee issues an `interaction` signal after training. A Weaver’s LTS reflects successful trainees. Low‑quality Weavers lose weight. |
| 10% solidarity redistribution fairness | LTS‑weighted redistribution | BAZs with higher aggregate LTS (trustworthy governance) receive more redistribution, creating incentive for good governance. |
| Participatory budgeting Sybil attacks | LTS‑weighted votes | Each participant’s vote weight = their LTS. Sybil accounts have near‑zero LTS. |

### 3.4 Meta‑Governance Framework

| Vulnerability (from Meta‑Governance) | ITP Mechanism | How It Solves |
|---------------------------------------|---------------|----------------|
| Institutional capture of councils | TIM + trust‑weighted voting | Capture requires controlling many independent high‑trust nodes – TIM collapses collusion rings. Four‑criteria audit becomes computational. |
| Conscious refuser retaliation | Shock propagation (restorative hold) | If a council penalises a refuser, that action is a Trust Signal. The refuser’s endorsers can issue `constraint`, freezing the council’s decision weight. |
| System Canary ignored | High‑weight warning signals | Canaries are certified nodes with special Trust Signals. Ignoring them triggers automatic integrity review (by TIM detecting council inaction). |
| Cognitive monoculture (only text‑based deliberation) | Multi‑modal Trust Signal attachments | Signals can include audio, video, diagrams. System Sanity Audit checks whether non‑textual signals are systematically discounted. |
| Permanent coordination structures (capture risk) | SAFs with TTL | Every meta‑governance body is a SAF that auto‑dissolves after TTL (e.g., 2 years). Renewal requires active participation – no permanent capture. |

## 4. Implementation Phases

ITP integration is designed to be incremental, respecting the GGF’s existing “BAZ Starter Pack” and phased rollout.

### Phase 1 (Year 1-2) – Hearts Treasury Integrity

**Goal:** Prevent fraud in Hearts redemption and Heartstarter matching.

**Deliverables:**
- Deploy a lightweight ITP relay network (Nostr‑style) for the pilot BAZs.
- Implement **TIM** for set of recipients endorsing a Community Provider.
- Hearts Treasury requires τ > 0.6 for any redemption above a small threshold (e.g., 100 Hearts).
- Heartstarter match fund releases second tranche only after TIM‑verified independent endorsements.

**Success metrics:**
- Zero successful collusion‑based fraud in pilot (target 100% detection).
- Additional latency for redemption `<` 2 seconds.

**GGF components affected:** Financial Systems §15 (Hearts Treasury), AUBI §7.4 (Heartstarter).

### Phase 2 (Year 2-3) – Proof of Care & AUBI Layer 2

**Goal:** Replace manual / AI‑only verification with cryptographic trust for care and ecological contributions.

**Deliverables:**
- Extend Trust Signal schema to support LMCI‑A vector (Love, Meaning, Connection).
- Community Providers must collect signed Trust Signals from recipients for each care act.
- AUBI Layer 2 bonuses are calculated from aggregated LTS of the provider (across all recipients).
- Community Weavers issue `endorsement` signals for providers they audit; these are weighted by the Weaver’s own LTS.
- Implement **restorative hold** (GGF profile) for dispute resolution.

**Success metrics:**
- 90% of care acts logged as Trust Signals in pilot BAZs.
- Reduction in Layer 2 bonus disputes by >80%.

**GGF components affected:** AUBI §5.2 (Layer 2), Nested Economies §8 (Community Weavers).

### Phase 3 (Year 3-5) – Meta‑Governance & Cross‑BAZ Coordination

**Goal:** Enable trust‑weighted voting, capture‑resistant councils, and ephemeral Scale‑Adaptive Fields for inter‑BAZ decisions.

**Deliverables:**
- Social Resilience Council elections use trust‑weighted voting (LTS from BAZ members).
- ICTL structural changes (Tier B) are managed via SAFs – a temporary field forms, sets the new rate, then auto‑dissolves after TTL (e.g., 90 days).
- System Canary nodes are certified and their `warning` signals trigger automatic integrity reviews.
- Multi‑modal Trust Signal attachments enabled for inclusive deliberation.

**Success metrics:**
- Four‑criteria Accountable Coordination audit pass rate ≥95% for all councils.
- SAF formation time for inter‑BAZ decisions `<` 1 hour.
- Zero successful capture attempts detected over 2 years.

**GGF components affected:** Meta‑Governance (all layers), Nested Economies §5.3 (Adaptive Governance), Financial Systems §14 (ICTL).

| **BAZ Council** | Council voting weight is LTS of each member (computed from interactions within the BAZ). | Each member’s LTS is calculated by an oracle node (or aggregated by smart contract). |

## 6. Cryptographic & Governance Requirements

To deploy the ITP‑GGF integration, the following must be specified or created:

### 6.1 Technical Requirements

- **Relay infrastructure:** At least 3–5 community‑run relays per BAZ (Nostr or libp2p). No central relay.
- **Key management:** Each participant (adult resident, Community Provider, Weaver) generates an Ed25519 key pair. Keys can be rotated with attestation.
- **Storage:** Each node stores signals for at least 90 days (expiry). Relays may store longer.
- **TIM parameters:** `d_max = 100` (neighbourhood size), `k_sample = 50` (endorser sampling), `α = 0.7` (topology weight), `τ_threshold = 0.6` for trust decisions.
- **Restorative hold period:** 30 days default, extendable by Community Weaver.

### 6.2 Governance Requirements

- **Social Resilience Council** must adopt a resolution to recognise ITP‑based trust scores as valid input for Hearts Treasury and AUBI Layer 2.
- **Data sovereignty:** BAZs may choose to run their own relays and not share signals outside the bioregion (privacy mode).
- **Appeals process:** The Digital Justice Tribunal handles disputes about false Trust Signals. The restorative hold ensures no permanent damage before resolution.
- **Annual audit:** The Accountable Coordination Audit must include verification that TIM parameters are not being manipulated to exclude legitimate participants.

### 6.3 GGF‑Specific Parameter Recommendations

| Parameter | Default (ITP) | GGF Adaptation | Rationale |
|-----------|---------------|----------------|-----------|
| Shock propagation | Punitive (permanent reduction) | Restorative hold (30‑day freeze) | Aligns with Right Relationship |
| Distance attenuation λ(2) | 0.5 | 0.7 (less discount for neighbour BAZs) | Encourage cross‑BAZ cooperation |
| Minimum endorsers for trust threshold | 1 | 5 (for provider chartering) | Prevents lone endorser fraud |
| TIM discount τ for redemption | 0.0 (perfect collusion) | τ > 0.6 required | Allows some overlap but not full collusion |
| Trust Signal expiry | 1 year | 90 days for care acts | Encourages fresh verification |

## Conclusion

The Immanent Trust Protocol provides the missing cryptographic and game‑theoretic foundation for the GGF’s regenerative economic vision. By integrating ITP, the GGF gains:

- **Provable collusion resistance** (TIM theorem) – not just heuristic detection.
- **Universal endorser liability** without financial stake – aligning incentives for Community Providers and Weavers.
- **Ephemeral, capture‑resistant coordination** (SAFs) – replacing permanent institutions with auto‑dissolving structures.
- **Observer‑relative trust** – preserving local sovereignty while enabling cross‑BAZ cooperation.

The GGF adaptation profile ensures that these technical mechanisms operate within a restorative justice framework, honouring Indigenous principles and Right Relationship. Together, ITP and the GGF form a coherent stack for planetary coordination – from the smallest care act to global meta‑governance.
