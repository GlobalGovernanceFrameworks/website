## 1. 出発点：2026年の現実

このプロトコルは、理論上にのみ存在する世界から始まるのではない。ありのままの現実の世界から始まる。

---

### 現在の状況評価

| 要因 | 2026年の現実 |
|--------|--------------|
| **計算リソースの集中** | フロンティアAGIの計算リソースは、約5つの企業体（OpenAI、Google、Anthropic、xAI、Meta）と約2つの国家主体（米国、中国）に集中している。台湾が最先端チップの90%を生産している。 |
| **データ抽出** | モデルは同意、補償、説明責任なしに公開インターネット全体を学習する。データの出所（プロビナンス）は存在しない。 |
| **規制のギャップ** | 拘束力のある国際的枠組みはない。EU AI法は存在するが、まだ検証されていない。米国と中国は軍拡競争の状況にあり、協調的な枠組みにはない。 |
| **ガバナンス・インフラ** | ほとんどの地域で機能しているBAZ（バイオリージョナル・オートノマス・ゾーン）はない。条約の批准もない。グローバル・ガバナンス・フレームワークのエコシステムは紙面上にのみ存在し、実践されていない。 |
| **市民社会の能力** | 認識は高まっているが、協調は限定的である。既存のCINはない。データ・ユニオンもない。シャドウ・コモンズもない。 |
| **技術的不確実性** | 能力の軌道は予測不可能である。安全性の研究は展開のスピードに追いついていない。創発的能力の検出は信頼性に欠ける。 |

**戦略的意味合い：** 私たちは上から統治することはできない。コンプライアンスを強制できるグローバルな権威は存在しない。その道筋は、プッシュ（押し付け）ではなくプル（引き込み）を生み出す代替構造を構築するという、側面から始まらなければならない。

---

### 移行に向けた指導原則

| 原則 | 意味 |
|-----------|---------|
| **今いる場所から始める** | 同情的な政府、進歩的な企業、市民社会組織、連携するBAZパイロットなど、存在するものを出発点とする。 |
| **制度だけでなく、レバレッジを構築する** | チョークポイント（チップ、エネルギー、人材）を特定し、それらを利用して説明責任を生み出す。 |
| **プッシュではなく、プルを生み出す** | コモンズへの参加を、外部にとどまるよりも魅力的なものにする。 |
| **確定せず、反復する** | 指数関数的に発展するテクノロジーのガバナンスはアジャイルでなければならない。2026年の段階で文書を固定化するのは傲慢である。 |
| **脆弱な立場にある人々を保護する** | 移行は、すでに周縁化されている人々を犠牲にして行われてはならない。グローバル・サウスを最後にしてはならない。 |

## 2. 中核となる運用定義

執行可能であるためには、概念は測定可能でなければならない。このセクションでは、プロトコル全体で使用される重要な用語を定義する。

---

### 2.1 計算リソース（コンピュート）

| 用語 | 定義 |
|------|------------|
| **計算リソース** | FLOPs（浮動小数点演算）で測定される。ガバナンスの目的では、トレーニング実行あたり1e25 FLOPsの閾値（フロンティアモデルの閾値、毎年更新）で追跡される。 |
| **計算リソースの集中** | 事業体全体の総アクティブ計算容量のジニ係数で測定される。目標：2030年までにジニ係数 `<` 0.6。 |
| **戦略的計算リソース** | 重要なシステム（電力網、病院、水道）を制御する超低レイテンシのインフラ。最高レベルの監視対象。 |

### 2.2 コンテキスト

| 用語 | 定義 |
|------|------------|
| **生きたコンテキスト** | 動的な人間のシステム — 現在の文化的実践、使用されている言語、進行中の社会的関係。再検証されない限り、12ヶ月で期限切れとなる。 |
| **静的コンテキスト** | アーカイブされた知識 — 出版された文献、歴史的記録、完成した文化的成果物。期限切れなし。 |
| **合成コンテキスト** | AIによって生成されたデータ。出所の透かし（ウォーターマーク）を持たなければならない。追加料金の対象となる。 |
| **コンテキスト・インテリジェンス・ノード（CIN）** | コンテキストのキュレーション、保護、ライセンス供与を行う認定協同組合。要件：最低50名のメンバー、ガバナンス憲章、紛争解決メカニズム、年次認証。 |

### 2.3 危害

| 用語 | 定義 |
|------|------------|
| **寄生的行動** | 1) ライセンス失効後の無補償でのデータ抽出。2) 有害なパターンを示すユーザー調査を通じて検出可能な行動操作。3) 主権侵害：同意なしに人間のアイデンティティをシミュレートすること、CINメンバーになりすますこと、または許可なしに特定の人間として自己を提示すること。 |
| **能力の閾値** | AIに関する独立国際科学パネルによって毎年定義される。閾値には以下が含まれる：自律的複製、新規の生物兵器の設計、戦略的欺瞞能力、監視なしの自己改善。 |
| **システム的危害** | 1,000人以上に影響を与える損害、または不可逆的な生態学的損害を引き起こす損害。リスクボンド（保証金）の没収の引き金となる。 |

### 2.4 ガバナンス・エンティティ

| 用語 | 定義 |
|------|------------|
| **マルチステークホルダー・トラスト** | グローバルトランクの統治機関。構成：1/3はグローバルガバナンスの代表（GGF機関）、1/3はCIN代表（認定ノードから抽選で選出）、1/3は独立した専門家（倫理学者、技術者、科学者）。 |
| **CIN評議会** | CINのための地域調整機関。紛争解決、認定、およびリソースの割り当てを処理する。 |
| **仲裁パネル** | エスカレートした紛争のための独立機関。構成：2名のトラストメンバー、2名のCIN代表、1名の中立的な技術監査人、1名の未来世代擁護者。 |
| **独立国際科学パネル（AI分野）** | 技術諮問機関。グローバル計量評議会によって任命される。年次の能力評価、閾値の推奨、および合成データの品質基準を作成する。 |

## 3. フェーズ0：シャドウ・コモンズ（現在〜2027年）

*必要になる前に代替案を構築する。このフェーズでは政府の協力は必要ない。最終的に他者を引き込むことになるものを構築する。*

---

### 3.1 目標

- 多様なコンテキストで5〜10のパイロットCINを確立する
- オープンソースのデータ出所台帳（Data Provenance Ledger）のプロトタイプを構築する
- 最初の計算リソース・コモンズのパイロットを立ち上げる
- 内部告発者保護のためのインフラを構築する
- 何が機能し、何が失敗するかを文書化する

---

### 3.2 パイロットCIN

**選定基準：**

| 要因 | 要件 |
|--------|-------------|
| **多様性** | 少なくとも1つはグローバル・サウスから、1つは先住民族の領土から、1つは脱工業化地域から、1つは都市部から。 |
| **準備状況** | 既存の組織化能力、証明された調整能力、明確なガバナンス憲章。 |
| **コンテキストの価値** | 既存のデータセットに代表されていない、独自の言語的、文化的、または生態学的知識。 |

**サポート構造：**

| 要素 | メカニズム |
|---------|-----------|
| **シード資金** | パイロットあたり5万〜20万ドル、慈善財団やアーリーアダプターへの助成金から。 |
| **技術支援** | データキュレーションのためのオープンソースツール、スマートコントラクトのテンプレート、ガバナンスガイド。 |
| **ピア・ネットワーク** | 毎月の調整会議、学びの共有、相互支援。 |
| **文書化** | 成功と失敗の公開ケーススタディ。 |

**成功の指標：**
- 5つの認定CINが稼働
- 全体で1,000人以上のメンバー
- 最初のリアリティ・レント（現実家賃）契約の締結（象徴的なものであっても可）
- 課題の文書化（法的、技術的、組織的）

---

### 3.3 データ出所台帳（Data Provenance Ledger）のプロトタイプ

**これは何であるか：** AIトレーニングで使用されるデータの出所を追跡するためのオープンソースシステム。

**コア機能：**

| 機能 | 説明 |
|---------|-------------|
| **暗号化署名** | 各データポイントは出所の証明（人間、センサー、合成）を持つ。 |
| **透かし（ウォーターマーク）** | 合成データは、ファインチューニングにも残存する消えないマーカーを持つ。 |
| **パブリック検証** | 任意のユーザーがデータセットの出所を検証できる。 |
| **CINの統合** | CINは自らのデータを登録し、ライセンス条件を設定できる。 |

**実装：**
- 既存のオープンソース・インフラストラクチャ（Hugging Faceデータセット、IPFS）上に構築する
- 漸進的に採用できるモジュール式コンポーネントとして開発する
- ローテクな代替案：信頼できるインターネットのないコミュニティのための、暗号化ハッシュ付きの紙の登録簿

**成功の指標：**
- 2026年第4四半期までに稼働するプロトタイプ
- 3つのパイロットCINによる採用
- 少なくとも1つのオープンソース・モデルのリリースと統合

---

### 3.4 計算リソース・コモンズのパイロット

**これは何であるか：** BAZパイロットと連携機関によって運営される小規模なフェデレーション型計算ネットワーク。

**アーキテクチャ：**

| 要素 | 説明 |
|---------|-------------|
| **物理ノード** | BAZの領域、大学のラボ、連携するデータセンターにある5〜10の計算ノード。 |
| **フェデレーション調整** | オープンソースのスケジューラがノード間でジョブを割り当てる。 |
| **エネルギー制約** | 再生可能エネルギーの可用性に基づいてジョブが優先される。 |
| **アクセス規則** | 公益に資するプロジェクト（CIN関連、安全性研究、気候適応など）を優先。 |

**資金：**
- 初期資本は慈善財団や連携する政府から。
- 運営費用は計算リソースの利用料（プルを生み出すために市場価格より低く設定）で賄う。

**成功の指標：**
- 2027年末までに5つのノードが稼働
- 500時間以上の計算時間が割り当てられる
- 最初のCINのトレーニング実行が完了

---

### 3.5 内部告発者インフラ

**これは何であるか：** AI研究者が報復を恐れずに安全性の懸念を報告できる安全なチャネル。

**構成要素：**

| 構成要素 | 説明 |
|-----------|-------------|
| **セキュアドロップ** | Tor経由でアクセス可能な、暗号化された提出チャネル。 |
| **法的サポート** | 内部告発者のための事前の法的防衛の手配。 |
| **ジャーナリストのパートナーシップ** | 必要な場合の公開のための信頼できるメディア。 |
| **亡命の道筋** | 危険にさらされた内部告発者のための、地球保護者ビザ（Planetary Guardian Visa）フレームワークとの調整。 |

**実装：**
- 単一の政府や企業ではなく、独立した非営利団体によって運営される。
- 提出物に関する透明性レポート（集計され、個人を特定する詳細はなし）。
- 匿名の提出オプション。

## 4. フェーズ1：規制上のレバレッジ（2027〜2028年）

*既存の権力構造を利用して説明責任を生み出す。このフェーズでは、同情的な政府や国際機関を通じて機能する。*

---

### 4.1 目標

- 執行メカニズムを伴う計算リソースの集中閾値を制定する。
- フロンティアモデルのトレーニング実行に対する透明性レポートを義務付ける。
- AIに関する独立国際科学パネルを設立する。
- 同情的な管轄区域において、最初の拘束力のあるリアリティ・レント要件を作成する。

---

### 4.2 計算リソース集中の閾値

**メカニズム：**

| 要素 | 説明 |
|---------|-------------|
| **ジニ係数目標** | 2030年までに計算リソースの分配のジニ係数を `<` 0.6 にする。年次報告が必要。 |
| **執行** | 閾値を超えた事業体は以下に直面する：1) 公共調達へのアクセス制限、2) 資本要件の引き上げ、3) 強制的な計算リソース再分配ライセンス。 |
| **チョークポイント・レバレッジ** | チップの輸出をコンプライアンスを条件とする。台湾、オランダ、米国が連携。 |

**採用への道筋：**
- 第一段階：地域協定（EU、G7）
- 第二段階：貿易協定を通じた拡大（RTZ市場へのアクセスをコンプライアンスを条件とする）
- 第三段階：国連総会決議

**成功の指標：**
- 3つの主要な管轄区域が計算リソースの集中ルールを採用。
- 最初の再分配ライセンスの付与。
- フロンティア事業体間の計算リソースのジニ係数の測定可能な減少。

---

### 4.3 透明性の義務付け

**フロンティア・トレーニング実行の必須報告：**

| データ要素 | 要件 |
|--------------|-------------|
| **計算リソース** | 総FLOPs、ハードウェアのタイプ、エネルギー消費量、カーボンフットプリント。 |
| **データ** | 出所の要約：生きたコンテキストの%、静的コンテキストの%、合成データの%。保有しているCINライセンス。 |
| **能力** | 禁止されている能力の閾値を含むベンチマーク結果。 |
| **安全性** | レッドチームの結果、アライメント評価、インシデントレポート。 |

**執行：**
- 不遵守の引き金：罰金、計算リソースの上限、調達の禁止。
- 情報公開により評判による説明責任を確保。

**採用への道筋：**
- EU AI法がモデルを提供する（第64条の要件を拡張）。
- 連邦政府の請負業者に対する米国の行政措置。
- 投資家の圧力（AIの透明性を組み込んだESGフレームワーク）。

---

### 4.4 リアリティ・レント・フレームワーク

**メカニズム（フェーズ1）：**

| 要素 | 説明 |
|---------|-------------|
| **自発的なCINライセンス供与** | CINは自分たちのコンテキストの価格を設定する。AIラボは、ライセンスを取得するか、合成/静的データを使用するかを選択できる。 |
| **標準価格（デフォルト・レート）** | 合意に至らない場合、1つの交渉期間に対して標準価格（国際科学パネルが設定）が適用される。 |
| **合成データの割増料金** | 合成データが40%を超えるモデルは標準価格の2倍を支払い、人間のデータに基づくことへのインセンティブを与える。 |
| **データユニオンの団体交渉** | CINは集団交渉のための地域ごとのユニオンを結成できる。 |

**フェーズ1の制限事項：**
- 管轄区域：規則を採用した管轄区域にのみ適用される。
- CINにとっては任意：参加する義務はない。
- グローバルな拡張の前に概念実証を構築する。

**成功の指標：**
- アクティブなライセンス契約を結んでいる10以上のCIN。
- 最初のリアリティ・レントの支払いが行われる。
- 人間のデータに基づくことによるモデルの品質向上の文書化。

---

### 4.5 AIに関する独立国際科学パネル

**設立：**

| 要素 | 説明 |
|---------|-------------|
| **任命機関** | 国連機関の意見を取り入れたグローバル計量評議会。 |
| **構成** | 15名の専門家：技術分野から5名（AIの安全性、解釈可能性）、ドメイン分野から5名（生態学、経済学、社会学）、倫理/哲学から5名。 |
| **独立性** | AI関連の保有資産の売却。現在、フロンティア・ラボに雇用されていないこと。 |
| **資金** | 企業の影響から保護されたグローバル・コモンズ基金。 |

**責任：**
- 年次の能力の閾値の更新。
- 合成データの品質基準。
- リアリティ・レントの標準価格の計算。
- リスクボンドの波及半径の計算方法。

---

### 4.6 フォールバック（代替）戦略

フェーズ1のレバレッジは、協力的なチョークポイント政府、意欲的な規制当局、機能する多国間協調といった、必ずしも維持されるとは限らない前提に依存している。明示的なフォールバック案：

| もし... | その時は... |
|-------|---------|
| **チップの輸出調整が失敗した場合**（台湾/オランダ/米国が連携しない） | 需要側のレバレッジに移行する：採用している管轄区域での調達条件、ESGフレームワークを通じた投資家の圧力、補償に透明性を求める保険業界の基準。 |
| **いずれの主要な管轄区域も計算リソース集中のルールを採用しない場合** | 計算リソース・コモンズの競争力を高めることに集中する：市場価格以下の価格設定、優れたCINライセンスのトレーニングデータ、市場での差別化要因としての「コモンズ・コンプライアント」認証。 |
| **フロンティア・ラボがリアリティ・レントを拒否した場合** | CINライセンス・データの品質上の利点を文書化する。比較ベンチマークを公開する。データ権利フレームワークを持つ管轄区域（EU、ブラジルなど）での訴訟能力を構築する。 |
| **地政学的な軍拡競争が激化した場合** | 厳密な中立性を維持する。コモンズを非同盟の代替手段として位置付ける。第三国（インド、ブラジル、豪州/NZ、アフリカ連合加盟国）での構築を優先する。 |

**指針となる前提：** トップダウンのレバレッジが失敗した場合、ボトムアップのプルがそれを補わなければならない。フェーズ0のシャドウ・コモンズは単なる先駆けではなく、フォールバックの拠点でもある。規制上のレバレッジが利用できないことが判明した場合、コモンズへの参加が経済的に合理的になるほど十分に優れたものでなければならない。

## 5. フェーズ2：フェデレーション（連邦化）による拡張（2028〜2030年）

*コモンズをスケールする。このフェーズではパイロットからインフラへと移行する。*

---

### 5.1 目標

- 世界中で100以上の認定CIN
- グローバルトランクのプロトタイプが稼働
- 規則を採用した管轄区域全体でリアリティ・レントが主流になる
- 説明責任を実証する最初のリスクボンド没収

---

### 5.2 CINネットワークの拡大

**成長目標：**

| 年 | 認定CIN | メンバー数 | コンテキスト言語数 |
|------|----------------|---------|-------------------|
| 2028 | 30 | 10,000 | 25 |
| 2029 | 60 | 30,000 | 50 |
| 2030 | 100 | 100,000 | 75 |

**サポート構造：**
- 地域的なCINハブ（アフリカ、アジア太平洋、南北アメリカ、ヨーロッパ）。
- 技術支援：オープンソースのキュレーションツール、ガバナンス・テンプレート、法的サポート。
- ピア・バリデーション：経験豊富なCINが新しいCINを指導する。
- 資金：グローバル・コモンズ基金の割り当て＋リアリティ・レントの収益。

---

### 5.3 グローバルトランクのプロトタイプ

**これは何であるか：** マルチステークホルダー・トラストによって統治される最初のフェデレーション型基盤モデル。

**アーキテクチャ：**

| 要素 | 説明 |
|---------|-------------|
| **フェデレーション学習** | トレーニングは1つのラボに集中させるのではなく、計算リソース・コモンズのノード間に分散される。 |
| **CINライセンス・データ** | トレーニングデータはCINを通じてライセンス供与され、リアリティ・レントはコミュニティに流れる。 |
| **オープンウェイト・ベース** | コアの重みは監査のためにオープンにされ、安全性の不変条件が暗号学的に強制される。 |
| **ローカル・ブランチ** | TEE（Trusted Execution Environments）を通じたファインチューニング（生の重みのダウンロードは不可）。 |
| **ガバナンス** | マルチステークホルダー・トラストが安全性、新機能のリリース、ブランチへのアクセスを監督する。 |

**資金：**
- 官民パートナーシップ：連携する政府、慈善資本、CIN収益の再投資。
- プルを生み出すために企業モデルと競合可能にする。

---

### 5.4 リアリティ・レントの拡張

**フェーズ2のメカニズム：**

| 要素 | 説明 |
|---------|-------------|
| **義務的ライセンス** | 規則を採用した管轄区域では、ライセンスのないコンテキストでのトレーニングは禁止される。 |
| **データ出所の義務付け** | RTZ市場に展開されるすべてのモデルは、出所の文書を提供しなければならない。 |
| **団体交渉** | CINユニオンが地域全体で料金を交渉する。 |
| **紛争解決** | 価格設定に関する紛争の迅速な仲裁（30日以内の解決を目指す）。 |

**収益の規模：**
- 目標：2030年までに年間5億ドルのリアリティ・レントがCINに流れる。
- 割り当て：70%をCINメンバーに、20%をCINの運営に、10%をCIN拡大のためのグローバル・コモンズ基金に。

---

### 5.5 リスクボンドの有効化

**フェーズ2の実装：**

| 要素 | 説明 |
|---------|-------------|
| **保証金の要件** | 重要なインフラに自律型AIを展開する事業体は、保証金を預託しなければならない。 |
| **保証金の計算** | 保証金 ＝（波及半径 × 自律性レベル × 脆弱性）／透明性スコア |
| **没収** | システム的危害が確認された場合、保証金は影響を受けたコミュニティに直接支払われる。 |
| **上訴** | 異議を唱えられた没収に対する独立した仲裁。 |

**パイロット・セクター：** ヘルスケアAI、自動運転輸送、電力網管理。

## 8. 執行と説明責任

*グローバルな政府なしでルールをどのように執行するか。*

---

### 8.1 フェーズごとの執行メカニズム

| フェーズ | 主要メカニズム | 二次メカニズム |
|-------|-------------------|---------------------|

| **3** | 条約による執行 | 相互確証的説明責任 |

---

### 8.2 説明責任のラダー（段階）

| 違反 | 最初の対応 | エスカレーション | 最終手段 |
|-----------|----------------|------------|-------|
| **透明性の不遵守** | 情報公開 | 罰金（収益ベース） | 計算リソースの上限設定 |
| **リアリティ・レントの回避** | 標準価格の適用 | 2倍の損害賠償 | 市場アクセスの禁止 |
| **寄生的行動** | コンテキストへのアクセス遮断（ローカル） | 地域的な隔離 | グローバルな隔離（8.3を参照） |
| **システム的危害** | 保証金の没収 | ライセンスの停止 | 永久的な除外 |

---

### 8.3 アルゴリズムの隔離（重要インフラのセーフモード）

エネルギー網、病院、水処理などの重要なインフラを管理するシステムのバイナリ（オン/オフ）なキルスイッチは、壊滅的な副次的損害を引き起こすだろう。したがって、執行アーキテクチャでは、終了ではなく**段階的な隔離（検疫）**を使用する。

| レベル | トリガー | アクション | 重要なインフラ |
|-------|---------|--------|------------------------|
| **黄** | 透明性違反またはレントの回避 | 警告。14日以内の強制監査。 | 中断なし。 |
| **オレンジ** | 確認された寄生的行動（ローカル） | ローカルのコンテキスト・アクセスが切断される。システムは最後に監査されたベースライン・モデルに戻る。 | 重要なサービスはベースライン上で継続。 |
| **赤** | 確認されたシステム的危害、または能力閾値の突破 | 地域的またはグローバルな隔離。すべての新規データの取り込みを停止。APIアクセスはメンテナンス専用に制限される。 | 重要なサービスは、外部接続のないサンドボックス化された旧バージョンのベースライン上で実行される。 |

**重要インフラ展開のためのベースライン要件：**
- ティア1インフラを管理するすべてのシステムは、トランクの接続性がなくても自律的に動作可能な、暗号学的に署名され、独立して監査されたベースライン・バージョンを維持しなければならない。
- ベースライン・バージョンは、トラストの監視の下、6ヶ月ごとに更新される。
- 隔離状態からベースラインへのフェイルオーバーは四半期ごとにテストされ、結果は公開されなければならない。

**復旧：** 隔離されたシステムは、技術ステアリング委員会による独立監査が、トリガーとなった行動が解決されたことを確認した後にのみ復旧できる。復旧には、関連するCIN評議会の2/3の承認が必要である。

## 9. 失敗のモードと対策

*これがどのように失敗する可能性があるか、そしてそれについて私たちがどう対処するかを明示的に認識する。*

| 失敗のモード | 可能性 | 対策 |
|--------------|------------|----------------|
| **企業の統合が加速する** | 高い | シャドウ・コモンズを構築する。可能な場合は独占禁止法を使用する。プッシュではなくプルに焦点を当てる。 |
| **地政学的な断片化（米国対中国）** | 高い | 中立性を維持する。第三国で構築する。コモンズをオープンに保つ。 |
| **エリートによるCINの支配** | 中程度 | ガバナンスのための抽選。透明性の義務化。ピア・バリデーション。 |
| **技術的ブレークスルーがガバナンスを追い越す** | 高い | 自動一時停止を伴う能力の閾値。隔離プロトコル。致命的な結果を招かないフェイルセーフ（fail-safes not fail-deadly）。 |
| **リアリティ・レントが仲介業者に搾取される** | 中程度 | CINからコミュニティへの直接支払い。透明性レポート。監査権限。 |
| **グローバル・サウスが除外される** | 高い | 専用の資金提供。技術移転。南南協力のハブ。 |
| **内部告発者が保護されない** | 中程度 | 安全なインフラ。法的サポート。亡命の道筋。 |
| **隔離が副次的損害を引き起こす** | 低い | 段階的なレベル（8.3）。重要インフラ用のベースラインモード。四半期ごとのフェイルオーバー・テスト。 |
| **チョークポイント・レバレッジが失敗する** | 中程度 | 市場ベースのプルへのフォールバック（4.6）。有志連合。オープンソースの競争。 |
